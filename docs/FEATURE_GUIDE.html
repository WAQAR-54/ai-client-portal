Feature Guide

AI Client Portal

Everything the app can do, organized by who uses it and where to find it. Give this to anyone who needs to understand the product — a new admin, a teammate, a client — without reading a line of code.

Overview

AI Client Portal is a single place for an organization to give its people access to AI chat models — OpenAI, Anthropic, Gemini, DeepSeek — under one roof, with real control over who can use what, how much it costs, and where the data goes.

Instead of everyone signing up for their own AI accounts, an admin connects the organization's own provider API keys once. From there, everything is managed centrally: which models are available, which plan (tier) each person is on, how much they're allowed to spend or send, and a full paper trail of who did what.

The short version: people chat; managers watch their team's usage; admins control access, cost, and compliance for their department; one SuperAdmin controls the whole organization, including which AI providers are connected at all.

Who can do what

Four roles, each one a superset of the one before it. A Manager can do everything a User can, plus their own tools; an Admin everything a Manager can, plus admin screens scoped to their department; a SuperAdmin everything everywhere, with a handful of powers no one else gets at all.

User

  • Chat with any model their plan allows
  • Use Compare mode, attachments, export, templates (if enabled)
  • See their own usage and request a plan upgrade
  • Manage their own profile, password, MFA, theme, notifications

Manager

  • Everything a User can do
  • "My Team" dashboard — usage per team member
  • Narrow which org-enabled models the team can use
  • Hand out individual model access from an admin-approved pool
  • Remove someone from the team (not the account itself)

Admin

  • Full admin console, scoped to their own department
  • Manage users, teams, limits, usage, audit log, feedback
  • Promote/demote between User ↔ Manager only
  • Set the department's system prompt & shared templates
  • MFA is mandatory whenever SuperAdmin turns it on

SuperAdmin

  • Everything, unscoped, across every department
  • Connect AI providers, sync & approve models
  • Define plans, budgets, routing & compliance rules
  • Branding, feature visibility, email/SMTP settings
  • MFA is always mandatory, cannot be turned off
One detail worth knowing: an Admin's power stops at their own department — they cannot see or touch another department's users, budget, or settings. A SuperAdmin has no such boundary.

Chat

UserManagerAdminSuperAdmin

The everyday screen, and the reason the product exists — everyone, regardless of role, lands here to actually talk to a model. Every feature below can be individually switched on or off per role from the admin's Feature Visibility page, so not every organization will see all of them.

Starting and managing conversations

New conversation, pin, search, delete

The sidebar lists every past conversation, grouped by date, with the most recent at top. Pinned conversations get their own section above the rest so they never scroll out of reach.

How: click New conversation to start fresh. Hover any conversation for the pin and delete icons. The search box above the list filters by title as you type. Deleting is a soft delete — the record is kept for audit, just hidden from view.

Choosing a model

Model picker & Smart Routing

By default the app picks a model automatically for every message — either an admin-defined rule ("if this looks like code, use GPT-4o"; "if there's an image, use a vision model") or, failing that, a general complexity check. Anyone can override this and pick a specific model instead.

How: open the model dropdown at the top of the chat, or the quick-pick chips above the message box. A model the current plan doesn't include shows a lock and which plan unlocks it — clicking it opens the upgrade-request flow instead of switching.

Compare mode (Arena)

Send one prompt to two different models at the same time and see both replies side by side — useful for genuinely comparing quality, tone, or speed before trusting one model with real work.

How: use the Chat/Compare switch above the message list, pick two models, and send. A "pick a winner" control records which reply was actually better, purely for visibility — it never changes how the app routes future messages automatically. Some plans cap how many Compare exchanges are allowed per day.

Working with content

File attachments

Attach a file to a message so the model can read it as context — PDFs, Word/Excel docs, plain text, CSV, Markdown, JSON, and images.

How: the paperclip icon in the composer. Size limits and which file types are allowed can be tightened per user or department from the admin side (see Limits).

Export a conversation

Take a full conversation out of the app as a file — for sharing, archiving, or pasting into another document.

How: the export menu on an open conversation offers PDF, Markdown, and plain text.

Prompt templates

Reusable starting points for the message box — save your own frequently-used prompts, and see any shared templates an Admin has set up for the whole department or team.

How: type / as the first character in the message box, or open the Templates panel from the composer, to insert one. Save the current draft as a new personal template from the same panel.

Edit & regenerate

Editing an earlier message of yours re-sends it and regenerates everything that came after — for correcting a typo or steering the conversation differently without starting over. Regenerate replaces just one AI reply with a fresh attempt.

Feedback (thumbs up/down)

Rate any AI reply and optionally explain a thumbs-down. This is purely for visibility to admins on the Feedback page — it's never used automatically to change which model gets picked.

Keeping track of usage

Usage widget & upgrade requests

A running total of how much of the current plan's daily/monthly allowance has been used, plus the plan name and, on a trial, how many days are left.

How: the Usage pill at the top of chat opens this. If it looks like more is needed, Request upgrade sends the request straight to an admin's Upgrade Requests queue — no need to email anyone.

Making it your own

Light/dark theme, language, and shortcuts

A quick theme toggle sits in the chat header; a full Light / Dark / System picker and language choice (English, Urdu, Arabic) live in Settings. Power users get a quick-switcher (Ctrl/Cmd+K) to jump between conversations without touching the mouse.

Guided tour

A short first-login walkthrough points out New chat, the usage widget, the model picker, and the admin/team link. It only shows once automatically, but can be replayed anytime from Settings.

My Team

Manager

A Manager's own dashboard — everything here is scoped to just their team, and every action here is additive or restrictive, never account-changing. A Manager cannot suspend an account, change a role, or move someone to a different plan; that's Admin territory.

Team dashboard

The team roster with each member's token usage, cost, and an engagement score, plus team-wide totals for all time and the current month.

Model access, two ways

A Manager has two separate, independent levers over which models their team can actually use:

Team-wide restriction — turn off a model for the whole team. This can only make the team's access narrower than what their Plan already allows, never wider.

Per-person grants — for individual members, hand out access to models from a pool an Admin/SuperAdmin has separately marked "manager-assignable." This is independent of the team's Plan, and a personal grant wins over the team-wide restriction for that one person.

Remove a team member

Removes someone from the team's roster only. Their login, plan, permission history, and past conversations are completely untouched — they simply stop being counted as part of this team.

Admin console — People & access

AdminSuperAdmin

An Admin's view here is scoped to their own department; a SuperAdmin sees everyone, everywhere, plus the department structure itself.

Admin → Users

Users

The master roster. Search and filter by role, active/suspended status, or plan. Each row shows their current plan, an engagement score, how many personal overrides they have, and recent request volume.

How: from here, add a new account, edit role/department/team/email, reset a password directly (no email round-trip needed), suspend or reactivate an account, and change one person's plan — or select several rows and change plan in bulk. Clearing a user's personal overrides resets them back to whatever their Plan and department rules would otherwise give them.
Admin → Teams

Teams

Create or delete the teams within a department — a Manager needs a team to exist before they have anything to manage. Shows each team's member count and manager.

SuperAdmin only → Departments

Departments

The org-chart itself. Create, rename, or delete departments, and set each one's monthly budget cap. From here you can also open a department's own system prompt (instructions baked into every AI reply for that department) and its shared prompt-template library.

Admin console — Plans & money

Admin (Limits only)SuperAdmin

Where subscription tiers, spending, and requests-for-more all live.

SuperAdmin only → Plans & access → Plan Management

Plan Management

Defines every subscription tier the organization offers — token/message/session/budget caps, which specific models the plan includes, which features it grants (file upload, export, priority routing, model selection, and more), demo/trial length, and which plan new signups land on by default.

SuperAdmin only → Capability Limits

Capability Limits

Numeric caps on specific actions rather than overall volume: maximum message length, maximum Compare-mode uses per day, and per-plan overrides for the Code Playground and Domain Generator daily-run limits.

Admin/SuperAdmin → Limits

Limits

Per-user or per-department overrides layered on top of whatever the Plan already sets — daily/monthly token caps, session message limits, a monthly spend cap, and file-upload size/type rules.

SuperAdmin only → Budget Automation

Budget Automation

Once a user's month-to-date spend crosses a chosen percentage of their budget cap, new replies are automatically switched to a cheaper fallback model instead of being blocked outright — spend gets capped without anyone hitting a hard wall mid-conversation.

Admin/SuperAdmin → Upgrade Requests

Upgrade Requests

The queue of "please upgrade my plan" requests users file from the chat usage widget. Approve one to jump straight to that person's row on Users and change their plan, or dismiss it.

Admin console — Automation & routing

SuperAdmin

How the app decides which model actually handles a message, before the user's own manual choice is even considered.

SuperAdmin only → Automation → Smart Routing

Smart Routing rules

"If the message looks like code / is a short casual question / has an image attached / has a long document attached, use model X" — a priority-ordered list of rules, checked before the app falls back to its own general complexity-based routing. Only applies when the user hasn't manually picked a model.

SuperAdmin only → Compliance Routing

Compliance Routing

A per-department hard ceiling on where requests are allowed to go at all — currently either "no restriction" or "EU-hosted models only." This sits on top of everything else (plan, team, personal grants) and can only make access narrower, never wider.

Admin console — Compliance & data

SuperAdmin

Controls for organizations with real data-handling obligations — none of this is on by default.

SuperAdmin only → Retention & Approval

Retention & Provider Approval

Two things live here: how long a department's conversations are kept before permanent deletion (30 days / 90 days / 7 years / forever), and the compliance sign-off every newly-connected AI provider must clear before any of its models can be enabled at all.

SuperAdmin only → Data Handling

Data Handling

Org-wide switches: restrict chat to zero-data-retention models only, turn PII scanning of outgoing messages on or off, mark which connected providers train on customer data, and configure what happens when the three built-in PII checks (national ID numbers, credit card numbers, phone numbers) catch something — block it, redact it, or just warn.

Admin console — Models & providers

SuperAdmin

Connecting real AI providers and deciding exactly which of their models the organization actually uses.

SuperAdmin only → Models → Providers

Providers — the real workflow

This is the only place API keys are ever entered.

1. Connect — paste a provider's API key. It's tested live against the provider before anything is saved, so a bad key is never stored; a good one is encrypted, and only its last 4 characters are ever shown again.

2. Sync — pulls that provider's current model list. Run it again anytime ("Resync") to pick up new models or catch retired ones.

3. Approve — every newly-connected or freshly-synced provider sits in "Pending" on the Retention & Approval page until a SuperAdmin signs off. Nothing from a pending provider can be turned on for chat.

4. Enable models — once approved, flip on the specific models that should actually be usable. A model can also be separately marked "manager-assignable," making it eligible for Managers to hand out individually via My Team.

5. Region — record where a provider actually hosts requests; this is what Compliance Routing's EU-only rule checks against.

Disconnecting a provider clears its key and force-disables every model that came from it.

SuperAdmin only → Models → Models (legacy)

Models (legacy)

An older, simpler model registry kept for organizations that set models up before the Providers workflow existed. Enable/disable a model, edit its display name and per-1M-token pricing, delete one that's never been used, or open its per-user allow/deny list.

Admin console — Monitoring & logs

AdminSuperAdmin

Everything an admin needs to answer "what happened, and how much did it cost" after the fact.

Admin/SuperAdmin → Usage & Cost

Usage & Cost

The spend dashboard: a per-user table of requests, tokens, and estimated cost (filterable by user, model, date range), a weekly cost trend, spend by provider, and how much the built-in response cache has saved. Exportable as CSV or Excel; a SuperAdmin also gets a cross-department monthly summary built for chargeback.

Admin/SuperAdmin → Audit Logs

Audit Logs

A searchable trail of every admin action taken in the app — who did it, what it was, what changed from and to, and when. The first place to check when something changed and nobody's sure who did it.

Admin/SuperAdmin → Feedback

Feedback

Every thumbs up/down and comment users have left on AI replies, filterable by rating, model, or user — read-only visibility into how well the AI is actually landing.

SuperAdmin only → Email Logs

Email Logs

Every email the app has actually sent — recipient, subject, whether it sent or failed, and whether it was opened — plus the SMTP connection settings that make outbound email work at all, and a "send test email" button to confirm they're actually correct before relying on them.

White-label the portal

Replace the default name, tagline, logo, and favicon with the organization's own, everywhere at once — the sidebar, the browser tab, and the login page all update immediately. A logo replaces the text name entirely rather than sitting next to it. Reset to defaults at any time.

Code Playground & Domain Generator

UserManagerAdminSuperAdmin

Two focused, single-purpose tools, separate from chat. Both are direct-link-only — there is no link to them in the main sidebar — and both are switched on or off per role from Feature Visibility (off by default for User/Manager, on for Admin/SuperAdmin).

Code Playground

Pick a model (grouped by provider, each labeled Fast / Balanced / Powerful), describe what the code should do, and run it in a simulated sandbox. Each run counts against a daily quota — 20 by default, adjustable per plan in Capability Limits.

Domain Generator

Describe a business idea, optionally filter by TLD (.com / .co / .pk / .uk), and get 5 AI-suggested brandable domain names — each one checked for live availability via real WHOIS lookups, not a guess. Same daily-quota pattern as the Playground (20/day by default).

Security & login

What keeps an account safe, and what happens when something goes wrong at the login screen.

Password reset

The standard "forgot password" flow — request a reset, get an emailed link, set a new one. The same confirmation message shows whether or not the email actually exists on an account, so the flow itself can't be used to check who has an account here. An Admin can also reset someone's password directly from Users, no email needed.

MFA (email one-time code)

A 6-digit code emailed at login, valid for 10 minutes, with a resend option and a 5-attempt limit before the login has to start over.

Who's required to use it: Admin and SuperAdmin, whenever the org-wide "MFA required for Admins" switch is on (Feature Visibility) — they can't opt out while it's on. For User and Manager it's entirely optional, turned on or off per-person from Settings → Security.

Account lockout

5 wrong password attempts locks that account for 20 minutes, with a dedicated "you're locked out, try again in..." screen rather than a generic error. A single successful login resets the counter.
